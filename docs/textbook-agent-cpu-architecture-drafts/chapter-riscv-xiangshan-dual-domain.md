# 从 RISC-V 小核与香山复杂前后端到双域 Agent CPU

## 1. 引言：从可教学 CPU 到可承载 Agent 的机器

理解 Agent CPU，不能只从大模型或工具调用开始。更稳妥的路径，是先回到计算机体系结构本身：一端是 E203 这类 RISC-V 小核，强调清晰、可实现、可教学；另一端是香山这类高性能开源处理器，强调复杂前端、深流水、乱序后端和可扩展验证。Agent CPU 并不是要简单替代它们，而是要借用二者的思想，重新划分“谁负责确定性控制，谁负责 Agentic 执行”。

本章提出一个过渡性视角：以 RISC-V 小核为控制面基线，以香山前后端为复杂机器模板，最终形成 **Super Domain + Agent Domain** 的双域 Agent CPU。

## 2. E203 小核：控制面的最小可信基线

E203 一类小核的价值，不在于性能峰值，而在于它把 CPU 的基本责任压缩到容易理解的范围：取指、译码、执行、访存、写回，中断异常，CSR 控制，以及可预测的软件栈接口。对于 Agent CPU，这类小核提供的是 **可信控制面** 的范式。

在 Agent 系统中，并不是所有逻辑都应该进入高动态的 Agent Domain。任务准入、权限检查、预算扣减、恢复点提交、工具调用授权、异常收敛等流程，需要一个稳定、可审计、低复杂度的控制核。RISC-V 的优势在于 ISA 简洁、特权级清晰、CSR 机制自然适合承载控制状态。Agent CPU 可以把一组 Agent 相关控制寄存器视为扩展 CSR，例如任务 ID、权限票据、上下文窗口编号、预算计数器、证据账本指针等。

因此，小核的启发是：Agent CPU 不能一开始就追求“所有东西都智能化”。它需要一个朴素但可靠的根：用确定性的控制核管理非确定性的 Agent 行为。

## 3. RISC-V 控制面：从指令状态到任务状态

传统 RISC-V 控制面关注 hart、特权级、中断、异常、页表和内存保护。Agent CPU 需要把这套思想提升一级：从“指令是否允许执行”，扩展到“任务片段是否允许推进”。

可以把 Agent 控制面理解为一组新的机器状态：

| 控制对象 | 传统 RISC-V 含义 | Agent CPU 扩展含义 |
|---|---|---|
| PC | 下一条指令地址 | 当前任务片段的执行位置 |
| CSR | 控制与状态寄存器 | 任务预算、权限、上下文与 ledger 指针 |
| Trap | 异常或中断入口 | 工具调用、权限拒绝、预算耗尽、需要人工确认 |
| PMP/MMU | 内存访问边界 | 文件、网络、模型、工具与长期记忆访问边界 |
| hart | 硬件线程 | 可隔离的 Agent 执行槽或任务 lane |

这个类比的关键不是把 Agent 强行变成普通进程，而是继承 RISC-V 的分层精神：普通执行路径尽量简单，敏感操作通过显式状态和 trap 进入控制域。Agent Domain 可以快速生成和执行代码，但凡涉及外部世界、长期记忆或安全边界，都应回到 Super Domain 仲裁。

## 4. 香山前端：FTQ、BPU、ICache 与 Agent 任务流

香山的启发来自另一端。现代高性能 CPU 的难点，首先不是算术单元，而是让前端持续、准确、低气泡地供应指令。FTQ 记录取指目标队列，BPU 预测控制流，ICache 供给指令字节，预译码和重定向机制共同维持前端吞吐。

Agent CPU 也有类似问题，只是“指令流”变成了“任务流”。Agent 不断在自然语言目标、仓库文件、工具输出、测试结果和历史记忆之间跳转。若每一步都临时搜索、临时构造上下文、临时判断下一步，整个系统会像严重前端断流的 CPU。

因此可以建立如下对照：

| 香山机制 | CPU 中的作用 | Agent CPU 中的对应思想 |
|---|---|---|
| FTQ | 保存预测取指块与重定向信息 | 保存候选任务片段、上下文投影和回退点 |
| BPU | 预测分支方向和目标 | 预测下一类工具、文件区域、测试路径或检索方向 |
| ICache | 缓存热指令 | 缓存热提示词片段、常用 repo 摘要、API schema 与工具模板 |
| 前端重定向 | 分支错误后恢复正确路径 | 计划失败、测试失败或权限拒绝后的任务重规划 |

这说明 Agent CPU 的前端不是一个聊天窗口，而是一个面向任务事件的供应系统。它要提前准备上下文，预测可能的工具链，并在错误时快速重定向。

## 5. 香山后端：ROB、执行队列与可恢复 Agent 执行

香山后端展示了复杂执行如何仍保持精确状态。乱序执行允许指令在内部重排，但 ROB 保证最终提交顺序和异常精确。Load/Store Queue 处理内存相关性，物理寄存器和重命名机制消除伪相关，提交阶段把临时结果变成架构可见状态。

Agent CPU 也需要类似的“乱序内部、顺序提交”原则。多个 Agent 子任务可以并行探索：一个读文档，一个跑测试，一个生成补丁，一个分析日志。但这些动作不能无序污染主仓库、长期记忆和用户可见结论。Agent Domain 可以投机执行，Super Domain 必须控制提交。

对应关系如下：

| 香山后端机制 | Agent CPU 类比 | 设计含义 |
|---|---|---|
| ROB | 任务提交缓冲 | 只有通过验证的事件才能进入 ledger |
| Issue Queue | 待执行微操作池 | 待调度工具调用、代码片段、检索任务 |
| Rename | 物理资源重命名 | 临时工作区、沙箱文件、候选上下文版本 |
| Commit | 架构状态更新 | 写入仓库、记忆、报告或用户可见答案 |
| Flush | 清空错误路径 | 放弃失败计划和污染风险较高的中间产物 |

这个类比特别重要：Agent CPU 的性能不只来自并行，更来自可撤销。没有 ROB 思想，Agent 的“多路探索”很容易变成不可审计的副作用扩散。

## 6. 双域架构：Super Domain 与 Agent Domain

综合小核与香山，可以得到双域 Agent CPU 的基本分工。

| 域 | 核心职责 | 借鉴来源 |
|---|---|---|
| Super Domain | 权限、预算、任务准入、异常、提交、ledger、恢复点 | RISC-V 小核、CSR、trap、精确异常 |
| Agent Domain | 上下文投影、计划预测、工具编排、投机执行、多路探索 | 香山前端预测、乱序后端、ROB 提交 |

Super Domain 应该小而可信，像系统的特权控制核；Agent Domain 可以复杂而激进，像面向 Agentic workload 的高性能执行引擎。前者追求可证明的边界，后者追求吞吐和适应性。二者之间通过任务描述符、上下文描述符、权限票据和提交协议交互。

用一句话概括：**Agent Domain 负责“想很多办法并尝试”，Super Domain 负责“哪些尝试可以成为事实”。**

## 7. 小结

RISC-V 小核提醒我们，体系结构需要一个清晰、稳定、可验证的控制根。香山提醒我们，高性能来自复杂前端、预测、乱序和精确提交。Agent CPU 的双域设计正是在二者之间取桥：以 Super Domain 保存确定性边界，以 Agent Domain 承载动态任务流。这样，Agent 不再只是运行在 CPU 上的软件，而成为硬件可感知、可调度、可恢复的执行对象。
