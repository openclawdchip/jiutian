# 全书结构审稿与替换稿建议

## 一、总体判断

现有重写稿已经明显脱离早稿的工程笔记形态，具备教材雏形：每章有导读或开篇说明，有核心定义、类比、贯穿例子、小结与习题，语言比早稿平稳，读者可以沿着“工作负载出现、基本抽象、双域架构、APU-IR、内存与互连、任务型 Agent 执行模型”的线索进入主题。但从全书结构看，它还没有完全成为一本教科书，更像“若干讲义单元的合集”。主要问题有三类：第一，知识顺序仍有跳跃，任务型 Agent 的执行模型放在第 6 章太晚，导致前面多次解释 Agentic workload、任务、上下文、工具、状态，形成重复引入；第二，若干章节标题和术语保留了工程手册口吻，如 APU-IR、Super Domain、Agent Domain、Memory、NoC、trace、ledger、artifact 等直接进入一级标题，会让初学者先面对系统名词，而不是先理解概念；第三，旧稿中的产品名、项目名、本地工程语汇虽已大幅减少，但仍应在全书层面设定边界，避免 RISC-V、香山、E203、repo、API schema、compact、hunks 等案例语汇重新进入主线。

本书最适合定位为“面向智能体计算的计算机体系结构导论”，而不是某一款 Agent CPU 的设计白皮书。教材的主线应当是：先说明新的工作负载为什么要求新的体系结构问题，再建立智能任务的执行模型，然后抽象出任务、证据、权限、预算、状态与提交等基本概念，最后进入系统接口、内存数据移动、恢复提交、评价方法与案例。这样读者会先获得问题意识，再学习抽象和机制，而不是一开始就被专用名词包围。

## 二、需要删除、合并、重命名和顺序调整的内容

1. 建议把第 6 章提前到第 2 章。任务型 Agent 的执行循环是全书的教学底座，应在“Agentic workload 的出现”之后立即讲清楚。否则第 2 章讲任务、证据、投影、trace，第 3 章讲 Agent Domain，第 4 章讲任务图，第 5 章讲 context 与 trace，都会重复解释 Agent 是如何执行任务的。提前后，全书逻辑会变成“为什么出现这种负载”到“这种负载如何运行”，再到“体系结构要抽象和支撑什么”。

2. 建议将现第 2 章“Agent CPU 的基本抽象”改为“智能任务的体系结构抽象”。“Agent CPU”在标题中出现过早，容易暗示本书已经默认一种硬件实体；“体系结构抽象”更像教材语言，也能容纳任务、证据、投影、权限、预算、过程记录和候选提交。该章内部应把 trace 改称“过程记录”或“执行轨迹”，首次出现时括注 trace；把 ledger 改称“承诺账本”或“提交记录”，首次出现时括注 ledger；把 artifact 改称“中间产物”，首次出现时括注 artifact。英文术语可以保留，但不宜成为初学者必须先背的标题。

3. 建议现第 3 章“双域架构”保留，但标题改为“治理域与执行域”。Super Domain 与 Agent Domain 可作为括注术语出现。教材不应让英文命名承担概念解释的责任。章内“不是……而是……”句式较多，应减少否定式定义。例如“所谓双域，不是简单地把系统切成两个进程或两个模块”可改成“双域架构把智能执行中的全局治理权和任务执行权分开”。这样的写法更直接，也更像教材。

4. 建议现第 4 章标题从“APU-IR：Agent 与硬件之间的契约”改为“任务级中间表示”。APU-IR 作为本书提出的术语可以保留，但不宜直接压在主标题最前。该章内容有教材价值，尤其 ISA、ABI、编译器 IR 与任务级表示的类比很清楚；需要压缩工程式字段展示，避免读者误以为在学习某个配置文件格式。示例中的 task、graph、permissions、budget、evidence、trace 可保留一处，但应强调它是概念草图，不是规范语法。

5. 建议现第 5 章标题改为“状态、记忆与片上通信”。“Memory 与 NoC”更像芯片设计报告标题，且中英混排过硬。该章应先讲传统内存层次，再讲智能任务状态的四类对象，最后讲缓存、SPM、DMA、NoC 如何服务这些对象。当前顺序基本可用，但“ledger/context/artifact/trace”四类状态应更早出现，作为本章问题的总览，再进入各机制。

6. 旧稿中的“从 Branch Prediction 到 Task-State Recovery”“从 ROB Commit 到 Candidate Commit”“从 SPEC 到 Agentic Benchmark”不应全部删除，而应重组为后续章节。它们是体系结构课程中最有辨识度的部分，可以构成全书后半部分：预测与恢复、提交与副作用、评价与基准。早稿中的“RISC-V 小核与香山复杂前后端”建议降级为案例章或附录，不宜作为主线章节。RISC-V 和香山适合作为“传统处理器如何启发 Agent CPU”的实例，但若放在主线中，会使教材变成某些开源项目的导读。

7. 需要删除或改写的口吻包括：工程命令式表达、产品路线式表达、局部实现名词堆叠、以及过密的缩写。旧稿中 repo 摘要、API schema、代码 diff hunks、compact transaction、runtime、Task Predictor、RecoveryLedger 等语汇，适合放在教师备课材料或工程实现附注，不适合放入正文主线。主教材应优先使用“代码库摘要”“接口结构”“差异片段”“压缩恢复过程”“运行时系统”“任务路径预测器”“恢复记录”等中文表达。

8. 附录建议保留，但要有明确角色。附录不应成为正文删不掉内容的堆放处。建议附录 A 放术语表，统一 Agentic workload、Agent CPU、任务图、执行轨迹、承诺账本、中间产物、候选提交、治理域、执行域等中英文对照；附录 B 放 RISC-V 与香山案例；附录 C 放课堂项目或实验题；附录 D 放示例任务级表示。这样主线保持教材节奏，工程细节有去处。

## 四、前言重写稿

计算机体系结构课程通常从指令、流水线、缓存、虚拟内存和并行处理讲起。这些内容建立在一个共同前提上：计算机要执行的是程序，程序由较明确的输入、控制流和状态转移构成。今天，智能体系统正在把新的问题带到体系结构面前。用户给出的可能不是一次函数调用，而是一个目标；系统要做的也不只是生成一句回答，而是在多轮推理、工具调用、状态更新和结果验证中逐步完成任务。

本书讨论的 Agent CPU，并不是要用一个新名词替代传统 CPU，也不是宣称所有智能体能力都应由硬件直接完成。它关注的是一个更基础的问题：当“智能任务”成为重要工作负载时，体系结构应当提供哪些抽象、接口和机制，才能让这类任务被调度、约束、观察、恢复和评价。传统体系结构中的特权级、指令集、缓存、分支预测、重排序缓冲、异常恢复和基准测试，仍然是理解这些问题的重要出发点；只是它们需要被提升到任务、证据、权限、预算、执行轨迹和候选提交的层面重新解释。

本书面向具有基础计算机系统知识的读者，也尽量照顾刚进入该方向的学习者。书中不会把某个具体产品、框架或开源项目当作唯一答案，而是以教材方式建立概念：先解释智能体工作负载为何不同，再说明任务型 Agent 如何运行，随后讨论 Agent CPU 需要的抽象、双域结构、任务级中间表示、状态记忆系统、预测恢复机制、提交机制和评价方法。每章都安排例子、小结和习题，帮助读者把新概念落回熟悉的体系结构问题。

智能体计算仍处在快速发展阶段，许多设计不会只有一种正确实现。本书希望提供的不是封闭规范，而是一套可讨论、可教学、可扩展的思考框架。读者学完本书后，应能回答三类问题：智能任务为什么给体系结构带来新压力；传统 CPU 的哪些思想可以迁移，哪些地方必须改变；如果要设计一个支持长程智能任务的计算平台，应怎样处理任务表示、权限边界、状态移动、恢复提交和性能评价。

## 五、“本书结构”重写稿

本书按“问题、抽象、机制、评价”的顺序组织。

第一编介绍智能体工作负载。第 1 章说明智能体工作负载如何从传统程序、服务请求和模型推理中分化出来，并提出控制流动态、状态层次丰富、性能指标复合、过程需要验证等体系结构问题。第 2 章建立任务型 Agent 的执行循环，围绕目标、上下文、工具、观察、计划和状态变化解释智能任务如何推进。第 3 章在执行循环基础上抽象出任务、证据、投影、权限、预算、执行轨迹和候选提交，为后续章节提供共同语言。

第二编讨论 Agent CPU 的基本机制。第 4 章介绍治理域与执行域，说明为什么智能任务需要把全局约束和具体执行分开。第 5 章讨论任务级中间表示，它位于自然语言任务和底层执行平台之间，用来表达任务图、权限、预算、证据和执行轨迹。第 6 章转向状态与数据移动，说明承诺账本、上下文、中间产物和执行轨迹如何进入内存层次、显式工作区、数据搬运单元和片上通信网络。

第三编讨论复杂执行中的关键问题。第 7 章从分支预测类比任务路径预测，分析系统如何提前准备可能的行动路径，并在判断失败时重定向。第 8 章从重排序缓冲的提交思想出发，讨论候选提交、顺序审查和外部副作用控制。第 9 章集中讨论执行轨迹、上下文压缩和长任务恢复，说明系统如何在中断、失败或信息丢失后回到可继续执行的状态。第 10 章介绍 Agent CPU 的评价方法，既关注延迟、吞吐和资源消耗，也关注正确性、安全性、可恢复性和证据质量。第 11 章以传统处理器思想为案例，展示简洁控制核、高性能前端和精确提交机制对 Agent CPU 的启发。第 12 章回顾全书主线，并提出若干开放研究问题。

全书附录提供术语表、任务级表示示例、课堂实验建议和参考案例说明。附录的作用是帮助读者查阅和实践，正文则保持概念主线的连续性。

## 六、章节命名统一方案

章节名应优先使用中文概念名，英文缩写放在副标题或括号中。建议采用以下替换：Agentic Workload 的出现改为“智能体工作负载的出现”；Agent CPU 的基本抽象改为“智能任务的体系结构抽象”；双域架构：Super Domain 与 Agent Domain 改为“治理域与执行域”；APU-IR：Agent 与硬件之间的契约改为“任务级中间表示”；Memory 与 NoC：从状态到数据移动改为“状态、记忆与片上通信”；任务型 Agent 的执行模型改为“任务型 Agent 的执行循环”。小节命名也应减少否定式标题，例如“为什么传统 Cache 不够”可改为“传统缓存的边界”，“Trace 不是日志，而是恢复材料”可改为“执行轨迹作为恢复材料”，“为什么仅有 Agent ISA 不够”可改为“指令级接口的边界”。

最后，全书应统一“导读—正文—小结—习题”的章内结构。当前第 1 章有“本章导读”，第 5、6 章用“本章小结”，其他章用“小结”，格式不完全一致。建议每章固定为：本章导读、若干编号小节、本章小结、习题。这样版式稳定，读者也更容易把它当作一本完整教材，而不是连续写作草稿。
