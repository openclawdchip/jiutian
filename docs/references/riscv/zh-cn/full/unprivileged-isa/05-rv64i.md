# 第 5 章 RV64I 基础整数指令集，版本 2.1

本章描述 RV64I base integer instruction set。RV64I 建立在第 2 章描述的 RV32I 变体之上。本章只呈现与 RV32I 的差异，因此应与前面的章节结合阅读。

## 5.1 Register State

RV64I 将 integer register 和所支持的 user address space 扩宽到 64 bit（图 2.1 中 `XLEN=64`）。

## 5.2 整数计算指令

大多数 integer computational instruction 对 XLEN-bit 值进行操作。RV64I 提供额外的指令变体来操作 32-bit 值，这些变体通过 opcode 上的 `W` 后缀表示。这些 `*W` 指令忽略其输入的高 32 bit，并始终产生 32-bit signed value，也就是说 bits `XLEN-1` 到 31 相等。

compiler 和 calling convention 维护一个 invariant：所有 32-bit 值都以 sign-extended format 保存在 64-bit register 中。即使是 32-bit unsigned integer，也会把 bit 31 扩展到 bits 63 through 32。因此，unsigned 和 signed 32-bit integer 之间的转换是 no-op，从 signed 32-bit integer 转换为 signed 64-bit integer 也是 no-op。在该 invariant 下，现有 64-bit 宽 `SLTU` 和 unsigned branch compare 仍能正确作用于 unsigned 32-bit integer。类似地，对 32-bit sign-extended integer 执行现有 64-bit 宽 logical operation，也会保留 sign-extension property。为了保证 32-bit 值的加法和移位具有合理性能，需要少数新指令（`ADD[I]W`/`SUBW`/`SxxW`）。

### 整数 register-immediate 指令

```text
31       20 19 15 14 12 11 7 6 0
imm[11:0]  rs1 funct3 rd   opcode
12         5   3      5    7

I-immediate[11:0] src ADDIW dest OP-IMM-32
```

`ADDIW` 是 RV64I 指令。它把 sign-extended 12-bit immediate 加到寄存器 `rs1`，并在 `rd` 中产生正确 sign-extension 的 32-bit 结果。Overflow 被忽略，结果为完整结果的低 32 bit，并 sign-extended 到 64 bit。注意，`ADDIW rd, rs1, 0` 把寄存器 `rs1` 低 32 bit 的 sign-extension 写入寄存器 `rd`（assembler pseudoinstruction `SEXT.W`）。

```text
31      26 25    24 20 19 15 14 12 11 7 6 0
imm[11:6] imm[5] imm[4:0] rs1 funct3 rd opcode
6         1      5        5   3      5  7

000000 shamt[5] shamt[4:0] src SLLI  dest OP-IMM
000000 shamt[5] shamt[4:0] src SRLI  dest OP-IMM
010000 shamt[5] shamt[4:0] src SRAI  dest OP-IMM
000000 0        shamt[4:0] src SLLIW dest OP-IMM-32
000000 0        shamt[4:0] src SRLIW dest OP-IMM-32
010000 0        shamt[4:0] src SRAIW dest OP-IMM-32
```

按常量移位被编码为 `I-type` 格式的特化形式，使用与 RV32I 相同的 instruction opcode。待移位的 operand 位于 `rs1`，对于 RV64I，移位量编码在 I-immediate field 的低 6 bit 中。右移类型编码在 bit 30 中。`SLLI` 是 logical left shift（0 被移入低位）；`SRLI` 是 logical right shift（0 被移入高位）；`SRAI` 是 arithmetic right shift（原始 sign bit 被复制到空出的高位）。

`SLLIW`、`SRLIW` 和 `SRAIW` 是仅 RV64I 的指令，定义方式类似，但它们操作 32-bit 值并产生 signed 32-bit result。`imm[5] != 0` 的 `SLLIW`、`SRLIW` 和 `SRAIW` 编码被保留。

> 过去，`imm[5] != 0` 的 `SLLIW`、`SRLIW` 和 `SRAIW` 被定义为导致 illegal instruction exception；而现在它们被标记为 reserved。这是一个 backwards-compatible change。

```text
31       12 11 7 6 0
imm[31:12] rd  opcode
20         5   7

U-immediate[31:12] dest LUI
U-immediate[31:12] dest AUIPC
```

`LUI`（load upper immediate）使用与 RV32I 相同的 opcode。`LUI` 把 20-bit U-immediate 放入寄存器 `rd` 的 bits 31-12，并把最低 12 bit 置零。32-bit 结果被 sign-extended 到 64 bit。

`AUIPC`（add upper immediate to `pc`）使用与 RV32I 相同的 opcode。`AUIPC` 用于构造 pc-relative address，并使用 `U-type` 格式。`AUIPC` 在 20-bit U-immediate 后附加 12 个低位零 bit，把结果 sign-extend 到 64 bit，加到 `AUIPC` 指令的地址上，然后把结果放入寄存器 `rd`。

### 整数 register-register 操作

```text
31      25 24 20 19 15 14 12 11 7 6 0
funct7     rs2   rs1   funct3 rd   opcode
7          5     5     3      5    7

0000000 src2 src1 SLL/SRL     dest OP
0100000 src2 src1 SRA         dest OP
0000000 src2 src1 ADDW        dest OP-32
0000000 src2 src1 SLLW/SRLW   dest OP-32
0100000 src2 src1 SUBW/SRAW   dest OP-32
```

`ADDW` 和 `SUBW` 是仅 RV64I 的指令，其定义类似于 `ADD` 和 `SUB`，但它们操作 32-bit 值并产生 signed 32-bit result。Overflow 被忽略，结果的低 32 bit 被 sign-extended 到 64 bit，并写入 destination register。

`SLL`、`SRL` 和 `SRA` 对寄存器 `rs1` 中的值，按寄存器 `rs2` 中保存的移位量执行 logical left、logical right 和 arithmetic right shift。在 RV64I 中，移位量只考虑 `rs2` 的低 6 bit。

`SLLW`、`SRLW` 和 `SRAW` 是仅 RV64I 的指令，其定义方式类似，但它们操作 32-bit 值并产生 signed 32-bit result。移位量由 `rs2[4:0]` 给出。

## 5.3 Load 和 Store 指令

RV64I 将 address space 扩展到 64 bit。execution environment 会定义 address space 的哪些部分可合法访问。

```text
31       20 19 15 14 12 11 7 6 0
imm[11:0]  rs1 funct3 rd   opcode
12         5   3      5    7
offset[11:0] base width dest LOAD

31      25 24 20 19 15 14 12 11 7 6 0
imm[11:5] rs2 rs1 funct3 imm[4:0] opcode
7         5   5   3      5        7
offset[11:5] src base width offset[4:0] STORE
```

对于 RV64I，`LD` 指令从 memory 加载 64-bit 值到寄存器 `rd`。

对于 RV64I，`LW` 指令从 memory 加载 32-bit 值，并在存入寄存器 `rd` 前 sign-extend 到 64 bit。另一方面，`LWU` 指令对来自 memory 的 32-bit 值 zero-extend。`LH` 和 `LHU` 对 16-bit 值作类似定义，`LB` 和 `LBU` 对 8-bit 值作类似定义。`SD`、`SW`、`SH` 和 `SB` 指令分别把寄存器 `rs2` 低位中的 64-bit、32-bit、16-bit 和 8-bit 值存储到 memory。

## 5.4 `HINT` 指令

所有在 RV32I 中属于 microarchitectural `HINT` 的指令（见第 2.9 节），在 RV64I 中也都是 `HINT`。RV64I 中额外的 computational instruction 同时扩展了 standard 和 custom `HINT` encoding space。
