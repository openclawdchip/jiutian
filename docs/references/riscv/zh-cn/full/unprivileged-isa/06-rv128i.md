# 第 6 章 RV128I 基础整数指令集，版本 1.7

> “计算机设计中只有一个错误很难恢复，那就是没有为 memory addressing 和 memory management 提供足够多的 address bit。”  
> Bell and Strecker, ISCA-3, 1976.

本章描述 RV128I，这是 RISC-V ISA 的一个变体，支持 flat 128-bit address space。该变体是对既有 RV32I 和 RV64I 设计的直接外推。

> 扩展 integer register width 的主要原因是支持更大的 address space。目前尚不清楚何时会需要大于 64 bit 的 flat address space。在本文写作时，按 Top500 benchmark 衡量的世界最快 supercomputer 拥有超过 1 PB DRAM；如果所有 DRAM 都位于单一 address space 中，将需要超过 50 bit 的 address space。一些 warehouse-scale computer 已经包含更大量的 DRAM，而新的高密度 solid-state non-volatile memory 和高速 interconnect 技术可能推动对更大 memory space 的需求。Exascale system 研究正以 100 PB memory system 为目标，这会占用 57 bit address space。按照历史增长速度，2030 年前可能会需要超过 64 bit 的 address space。

> 历史表明，每当人们明确需要超过 64 bit address space 时，architect 都会围绕扩展 address space 的替代方案反复进行密集争论，包括 segmentation、96-bit address space 和 software workaround；直到最后，flat 128-bit address space 会作为最简单也最好的解决方案被采用。

我们目前尚未 freeze RV128 spec，因为可能需要基于 128-bit address space 的实际使用情况演进设计。

RV128I 建立在 RV64I 之上的方式，与 RV64I 建立在 RV32I 之上的方式相同：integer register 扩展为 128 bit（即 `XLEN=128`）。大多数 integer computational instruction 不变，因为它们被定义为对 XLEN bit 操作。RV64I 中对寄存器低位 32-bit 值进行操作的 `*W` integer instruction 被保留，但现在会把结果从 bit 31 sign-extend 到 bit 127。新增一组 `*D` integer instruction，它们对保存在 128-bit integer register 低位中的 64-bit 值进行操作，并把结果从 bit 63 sign-extend 到 bit 127。`*D` 指令在标准 32-bit 编码中消耗两个 major opcode（`OP-IMM-64` 和 `OP-64`）。

> 为了改善与 RV64 的兼容性，与 RV32 到 RV64 的处理方式相反，我们可能会改变解码方式：把 RV64I `ADD` 重命名为 64-bit `ADDD`，并在原先的 `OP-64` major opcode（现在重命名为 `OP-128` major opcode）中增加 128-bit `ADDQ`。

按 immediate 移位（`SLLI`/`SRLI`/`SRAI`）现在使用 I-immediate 的低 7 bit 编码；variable shift（`SLL`/`SRL`/`SRA`）使用 shift amount source register 的低 7 bit。

新增 `LDU`（load double unsigned）指令，使用既有 `LOAD` major opcode；同时新增 `LQ` 和 `SQ` 指令，用于加载和存储 quadword 值。`SQ` 加入 `STORE` major opcode，而 `LQ` 加入 `MISC-MEM` major opcode。

floating-point instruction set 不变，不过 128-bit `Q` floating-point extension 现在可以支持 `FMV.X.Q` 和 `FMV.Q.X` 指令，并支持额外的 `FCVT` 指令，用于与 `T`（128-bit）integer format 相互转换。
