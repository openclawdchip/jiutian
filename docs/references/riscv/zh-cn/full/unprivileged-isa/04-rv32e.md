# 第 4 章 RV32E 基础整数指令集，版本 1.9

本章描述 RV32E base integer instruction set 的 draft proposal。RV32E 是 RV32I 的缩减版本，面向 embedded system 设计。唯一变化是把 integer register 数量减少到 16 个。本章只概述 RV32E 与 RV32I 的差异，因此应在阅读第 2 章之后阅读。

> RV32E 被设计用于为 embedded microcontroller 提供更小的 base core。虽然我们曾在本文档 2.0 版本中提到这种可能性，但最初并不愿定义该子集。不过，考虑到对尽可能小的 32-bit microcontroller 的需求，并且为了预先避免这一领域的碎片化，我们现在把 RV32E 定义为继 RV32I、RV64I 和 RV128I 之后的第四个 standard base ISA。也有人有兴趣定义 RV64E，以减少高度线程化 64-bit processor 的 context state。

## 4.1 RV32E 程序员模型

RV32E 把 integer register 数量减少为 16 个 general-purpose register（`x0`-`x15`），其中 `x0` 是专用 zero register。

> 我们发现，在小型 RV32I core 设计中，排除 memory 后，上方 16 个 register 约占 core 总面积的四分之一。因此，移除这些 register 可节省约 25% core area，并相应降低 core power。

该变化需要不同的 calling convention 和 ABI。特别是，RV32E 只与 soft-float calling convention 一起使用。一个新的 embedded ABI 正在考虑中，它将同时适用于 RV32E 和 RV32I。

## 4.2 RV32E 指令集

RV32E 使用与 RV32I 相同的 instruction-set encoding，区别只是只提供寄存器 `x0`-`x15`。未来任何 standard extension 都不会使用因缩减 register-specifier field 而释放出来的 instruction bit，因此这些 bit 可用于 custom extension。

> RV32E 可以与当前所有 standard extension 组合。曾考虑过在 `F`、`D` 和 `Q` 扩展与 RV32E 组合时，把它们定义为具有 16 项 floating point register file，但最终决定不这样做。为了支持具有减少的 floating-point register state 的系统，我们打算定义一个 `Zfinx` 扩展，使 floating-point computation 使用 integer register，从而移除 floating-point load、store，以及 floating point register 与 integer register 之间的 move。
