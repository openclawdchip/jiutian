机器级 ISA，版本 

### 1.11
本章介绍机器模式（M-mode）下可用的机器级操作，即
RISC-V 系统中的最高权限模式。 M-mode 用于对硬件的低级访问
平台，是重置时进入的第一个模式。 M-mode 还可用于实现以下功能：
直接在硬件中实现太困难或太昂贵。 RISC-V 机器级 ISA
包含一个公共核心，该核心根据支持的其他权限级别进行扩展
以及硬件实现的其他细节。


### 3.1 机器级CSRs
除了本节介绍的机器级CSRs之外，M-mode代码可以访问所有CSRs
在较低的特权级别。

地址被转换和保护，就像当前特权模式设置为 MPP 一样。
指令地址转换和保护不受 MPRV 设置的影响。 MPRV 是
如果不支持 U-mode，则硬连线为 0。

记忆。当 MXR=0 时，只有从标记为可读的页面（图 

### 4.15 中的 R=1）加载才会成功。

MPRV和MXR机制的构思是为了提高M-mode例程的效率

需要在软件中进行地址转换。 MXR 允许加载指令字
来自标记为只执行的页面。
为了简单起见，MPRV和MXR无论特权模式如何都有效，但在正常情况下
仅在机器模式下针对短序列启用使用。
当前权限模式和MPP指定的权限模式可能有不同
XLEN 设置。当 MPRV=1 时，加载和存储内存地址被视为
当前的 XLEN 被设置为 MPP 的 XLEN，遵循第

SFENCE.VMA 指令在 S-mode 中执行时将引发非法指令异常。
当TVM=0时，在S模式下允许这些操作。当 S-mode 时，TVM 硬连线为 0
不支持。
TVM 机制允许客户操作系统提高虚拟化效率
在 S-mode 中执行，而不是在 U 模式下传统地虚拟化它们。这种方法避免了
需要捕获对大多数 S-mode CSR 的访问。
捕获 satp 访问，SFENCE.VMA 指令提供必要的挂钩
延迟填充影子页表。
TW（超时等待）位支持拦截 WFI 指令（参见第 

### 3.2.3 节）。当
TW=0，WFI指令在某些情况下不被阻止时可以在较低特权模式下执行
其他原因。当TW=1时，如果WFI在任何低权限模式下执行，则不会
在特定于实现的有界 time 限制内完成，WFI 指令会导致
非法指令异常。 time 限制可能始终为 0，在这种情况下 WFI 总是会导致
当 TW=1 时，低特权模式下的非法指令异常。当 TW 硬连线为 0 时
没有比 M 更小的特权模式了。
捕获WFI指令可以触发世界切换到另一个客户OS，而不是
浪费性地闲置在当前的客人中。
当实现 S-mode 时，在 U-mode 中执行 WFI 会导致非法指令异常，除非它在特定于实现的有界 time 限制内完成。 A未来修订版
该规范可能会添加一项功能，允许 S-mode 有选择地允许 WFI 处于 U 模式。
该功能仅在 TW=0 时有效。
TSR（陷阱SRET）位支持拦截管理程序异常返回指令SRET。
当TSR=1时，在S-mode中执行时尝试执行SRET将引发非法指令
例外。当TSR=0时，在S模式下允许该操作。当 TSR 硬连线为 0 时
不支持 S-mode。
必须捕获 SRET 才能在实现上模拟虚拟机管理程序扩展
不提供它。

### 3.5.6 幂等性 PMAs
幂等性 PMAs 描述对地址区域的读写是否是幂等的。主要
内存区域被假定为幂等的。对于 I/O 区域，读取和写入具有幂等性
可以单独指定（例如，读取是幂等的，但写入不是）。如果访问是非幂等的，即任何读或写访问都可能存在副作用，则推测或
必须避免冗余访问。
为了定义幂等性 PMAs，观察到的内存顺序发生了变化
冗余访问不被视为副作用。
虽然硬件的设计应始终避免对内存的推测或冗余访问
当区域标记为非幂等时，还需要确保软件或编译器优化不会生成对非幂等内存区域的虚假访问。
非幂等区域可能不支持未对齐的访问。对此类的访问未对齐
区域应该引发访问异常而不是地址未对齐异常，这表明
软件不应使用多个较小的访问来模拟未对齐的访问，这可能会导致
引起意想不到的副作用。

访问决定该访问是成功还是失败。匹配的 PMP 条目必须匹配
访问的所有字节，或者访问失败，无论 L、R、W 和 X 位如何。例如，
如果 PMP 条目配置为匹配四字节范围 0xC–0xF，则对 PMP 条目的 8 字节访问
范围 0x8–0xF 将失败，假设 PMP 条目是与这些条目匹配的最高优先级条目
地址。
如果 PMP 条目与访问的所有字节匹配，则 L、R、W 和 X 位确定是否
访问成功或失败。如果L位清零且访问权限模式为M，则访问
成功了。否则，如果设置了 L 位或者访问的特权模式为 S 或 U，则访问
仅当与访问类型相对应的 R、W 或 X 位被置位时才会成功。
如果没有PMP表项匹配M-mode访问，则访问成功。如果没有 PMP 条目与
S-mode或U-mode访问，但至少执行了一个PMP条目，访问失败。
失败的访问会生成加载、存储或指令访问异常。请注意，单个指令
可能会生成多个访问，这些访问可能不是相互原子的。如果一条指令生成的至少一个访问失败，则生成访问异常，尽管由指令生成的其他访问失败
该指令可能会成功，但会产生明显的副作用。值得注意的是，引用虚拟的指令
内存被分解为多次访问。
在某些实现中，未对齐的加载、存储和指令提取也可能被分解
分成多次访问，其中一些可能在访问异常发生之前成功。特别是，
通过 PMP 检查的未对齐存储的一部分可能会变得可见，即使另一个
部分未通过 PMP 检查。对于宽度大于的浮点存储，可能会出现相同的行为
XLEN 位（例如 RV32D 中的 FSD 指令），即使存储地址自然对齐也是如此。
