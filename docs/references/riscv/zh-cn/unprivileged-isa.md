## 前言

本卷定义 RISC-V 非特权指令集架构。它描述应用程序、编译器、汇编器、链接器、模拟器和硬件实现共同依赖的基础语义：整数寄存器、指令编码、控制流、访存、异常、标准扩展、内存一致性模型和扩展命名规则。与特权架构相比，本卷不规定操作系统或固件如何管理页表、中断控制器和特权 CSR；这些能力由执行环境和特权规范承接。

RISC-V 的设计目标是提供一个模块化 ISA：基础整数 ISA 保持小而稳定，常用能力通过标准扩展组合而成，特定实现还可以加入非标准扩展。软件可以通过 ISA 字符串和平台约定识别可用能力，硬件可以按面积、功耗、性能和应用领域选择实现子集。

## 1. 引言

RISC-V 将处理器抽象为一个或多个 hart。每个 hart 独立维护程序计数器、通用整数寄存器以及已实现扩展所需的架构状态。非特权代码运行在某个执行环境中；执行环境负责提供内存映射、设备访问、系统调用、异常处理和中断转发等服务。规范有意把 ISA 语义与具体平台分开，使同一 ISA 能用于裸机、操作系统、虚拟机、仿真器和专用运行时。

### 1.1 硬件平台术语

一个 RISC-V 硬件平台可以包含处理器核、hart、内存系统、I/O 设备和互连。hart 是 ISA 级别的执行实体；一个物理核可以包含一个或多个 hart。平台还可以定义内存区域的属性，例如可缓存性、原子性、可执行性和设备访问语义。非特权规范只描述 hart 执行指令时的可见行为，不固定平台拓扑。

### 1.2 软件执行环境与 hart

执行环境为非特权程序提供初始状态、地址空间、异常入口和系统服务。程序可以通过 `ECALL` 请求环境服务，通过非法指令、访存异常、断点等事件进入环境处理。规范不要求所有执行环境都支持相同的地址空间或系统调用 ABI；这些属于平台 ABI 或特权架构范围。

### 1.3 ISA 概览

RISC-V 基础整数 ISA 按 XLEN 分为 RV32I、RV64I 和 RV128I。RV32I 是 32 位地址和整数寄存器模型；RV64I 将整数寄存器扩展到 64 位；RV128I 预留更宽地址和整数模型。基础 ISA 提供整数算术、逻辑、移位、比较、分支、跳转、加载、存储、同步和环境调用能力。

标准扩展用单字母或 `Z*` 名称表示。例如 `M` 是整数乘除，`A` 是原子操作，`F/D/Q` 是浮点，`C` 是压缩指令，`Zicsr` 是 CSR 指令，`Zifencei` 是取指栅栏。标准通用组合 `G` 通常表示 `I`、`M`、`A`、`F`、`D`、`Zicsr` 和 `Zifencei` 的组合。

### 1.4 内存

非特权 ISA 将内存视为按字节编址的地址空间。加载从内存读出字节、半字、字、双字或更宽对象并扩展到寄存器；存储把寄存器低位写入内存。普通整数加载和存储默认使用小端字节序，但系统可以通过执行环境定义字节序。指令访问、数据访问和 I/O 访问的实际有效性由执行环境、平台内存映射和特权配置共同决定。

自然对齐访问通常是实现的高效路径。非对齐访问是否被支持、是否原子、是否触发异常，由执行环境接口定义。若执行环境保证某类非对齐访问可用，软件可以依赖该行为；否则可移植代码应按自然对齐方式组织数据。

### 1.5 基础指令长度编码

基础 ISA 使用固定 32 位指令，并要求指令地址按 4 字节对齐。当实现 `C` 压缩扩展时，16 位指令也合法，指令地址对齐可放宽到 2 字节。低两位用于指示指令长度：不全为 `11` 的编码表示 16 位压缩指令；低两位为 `11` 的编码进入 32 位或更长指令空间。较长指令编码为未来扩展保留。

实现的最大指令长度由 ILEN 表示。所有实现至少支持 32 位指令。若实现不支持某种长度或编码，取到该指令时应按非法指令处理，除非执行环境另有定义。

### 1.6 异常、陷入与中断

异常是由当前指令导致的同步事件，例如非法指令、断点、访存地址错误或访问错误。中断是异步事件，其可见性、优先级和处理入口由执行环境或特权架构定义。陷入是异常或中断导致控制权转移的统称。非特权规范只定义哪些指令可能产生异常，以及异常与指令语义的关系；具体陷入寄存器、向量入口和返回由特权架构定义。

如果指令地址未满足 IALIGN，跳转或分支指令会在目标地址处报告指令地址未对齐异常。对于支持 16 位指令对齐的实现，这类异常通常不会因 2 字节对齐目标产生。非法指令异常用于未实现、保留或当前环境不允许的指令编码。

### 1.7 未指定行为和值

规范标注为 UNSPECIFIED 的行为或值不由本卷约束。实现可以选择任何行为，但不应破坏已定义语义。保留编码不应被标准软件使用；未来规范可能赋予其含义。自定义编码空间可供非标准扩展使用，但软件应通过平台约定或发现机制确认其存在。

## 2. RV32I 基础整数指令集，版本 2.1

RV32I 是 RISC-V 的基础 32 位整数 ISA。它包含 32 个通用整数寄存器、一个程序计数器和一组固定 32 位指令格式。除寄存器 `x0` 恒为零外，通用寄存器由软件自由使用；ABI 进一步为寄存器分配调用约定名称。

### 2.1 程序员模型

RV32I 的整数寄存器为 `x0` 到 `x31`，每个 32 位。`x0` 读出始终为 0，写入被丢弃。程序计数器 `pc` 指向当前指令。规范本身不强制 ABI 名称，但常见 ABI 将寄存器命名如下：

| 寄存器 | ABI 名称 | 常见用途 |
|---|---|---|
| `x0` | `zero` | 常量 0 |
| `x1` | `ra` | 返回地址 |
| `x2` | `sp` | 栈指针 |
| `x3` | `gp` | 全局指针 |
| `x4` | `tp` | 线程指针 |
| `x5`-`x7` | `t0`-`t2` | 临时寄存器 |
| `x8`-`x9` | `s0/fp`-`s1` | 被调用者保存寄存器，`s0` 也可作帧指针 |
| `x10`-`x17` | `a0`-`a7` | 参数和返回值 |
| `x18`-`x27` | `s2`-`s11` | 被调用者保存寄存器 |
| `x28`-`x31` | `t3`-`t6` | 临时寄存器 |

基础 ISA 不包含条件码寄存器。比较结果通过分支指令或显式写入整数寄存器的比较指令表达。没有架构可见的栈机制，栈完全由 ABI 和软件约定管理。

### 2.2 基础指令格式

RV32I 使用六类主要 32 位格式：

| 格式 | 主要用途 | 字段组织 |
|---|---|---|
| R-type | 寄存器-寄存器算术逻辑 | `funct7 rs2 rs1 funct3 rd opcode` |
| I-type | 立即数算术、加载、`JALR`、环境指令 | `imm[11:0] rs1 funct3 rd opcode` |
| S-type | 存储 | `imm[11:5] rs2 rs1 funct3 imm[4:0] opcode` |
| B-type | 条件分支 | 分支立即数拆分在高低字段中，低位隐含为 0 |
| U-type | 20 位高立即数 | `imm[31:12] rd opcode` |
| J-type | `JAL` | 跳转立即数拆分在多个字段中，低位隐含为 0 |

所有寄存器字段位置在不同格式中尽量保持一致，便于译码。立即数统一按有符号数扩展到 XLEN，除少数明确按无符号解释的字段外。分支和跳转立即数以 2 字节为单位编码，以兼容压缩指令地址空间。

### 2.3 立即数编码变体

I-type 立即数位于指令高 12 位，按符号扩展参与运算。S-type 将存储偏移拆成 `imm[11:5]` 和 `imm[4:0]`。B-type 与 S-type 相似，但重排位以形成 13 位分支偏移。U-type 提供 20 位高位立即数，低 12 位为 0。J-type 提供 21 位有符号跳转偏移。

这种立即数布局让 `rd`、`rs1` 和 `rs2` 字段在多种格式中保持固定位置，同时把符号位放在指令最高位，方便并行符号扩展。

### 2.4 整数计算指令

`LUI` 将 20 位立即数放入目标寄存器的高 20 位，低 12 位填 0。`AUIPC` 将同样的高立即数加到当前 `pc`，用于构造 PC 相对地址。二者配合 I-type 或 S-type 访问可覆盖 32 位地址范围。

I-type 算术指令以 `rs1` 和 12 位符号扩展立即数为输入：

| 指令 | 语义 |
|---|---|
| `ADDI` | `rd = rs1 + imm`，忽略溢出 |
| `SLTI` | 有符号比较，`rs1 < imm` 时写 1，否则写 0 |
| `SLTIU` | 无符号比较；立即数先符号扩展再按无符号解释 |
| `XORI` | 按位异或立即数 |
| `ORI` | 按位或立即数 |
| `ANDI` | 按位与立即数 |
| `SLLI` | 逻辑左移，移位量来自立即数字段 |
| `SRLI` | 逻辑右移 |
| `SRAI` | 算术右移，复制符号位 |

R-type 算术逻辑指令使用 `rs1` 和 `rs2`：

| 指令 | 语义 |
|---|---|
| `ADD` | 加法，溢出按模 2^XLEN 截断 |
| `SUB` | 减法 |
| `SLL` | 逻辑左移，移位量取 `rs2` 低 `log2(XLEN)` 位 |
| `SLT` | 有符号小于比较 |
| `SLTU` | 无符号小于比较 |
| `XOR` | 按位异或 |
| `SRL` | 逻辑右移 |
| `SRA` | 算术右移 |
| `OR` | 按位或 |
| `AND` | 按位与 |

整数溢出不会自动产生异常。需要溢出检测的软件必须用比较和分支显式实现。`NOP` 的规范伪指令通常编码为 `ADDI x0, x0, 0`。

### 2.5 控制转移指令

`JAL` 将下一条指令地址写入 `rd`，并跳转到 `pc` 加有符号 J-type 偏移。若 `rd` 为 `x1`，它是常规函数调用；若 `rd` 为 `x0`，它是无链接跳转。`JALR` 以 `rs1 + imm` 作为目标，并清零目标地址最低位，然后把返回地址写入 `rd`。清零最低位既简化硬件，也允许软件在函数指针低位携带辅助标记。

条件分支比较两个寄存器，并在条件成立时跳转到 B-type PC 相对目标：

| 指令 | 条件 |
|---|---|
| `BEQ` | `rs1 == rs2` |
| `BNE` | `rs1 != rs2` |
| `BLT` | 有符号 `rs1 < rs2` |
| `BGE` | 有符号 `rs1 >= rs2` |
| `BLTU` | 无符号 `rs1 < rs2` |
| `BGEU` | 无符号 `rs1 >= rs2` |

分支不写返回地址。规范建议软件把顺序路径安排为常见路径，把不常见路径放到分支目标处，以利于预测和取指。无条件控制转移应使用 `JAL x0, target`，而不是永真条件分支。

### 2.6 加载与存储指令

加载和存储使用 `rs1 + imm` 计算有效地址。RV32I 提供字节、半字和字访问：

| 指令 | 访问宽度 | 结果扩展 |
|---|---|---|
| `LB` | 8 位 | 符号扩展 |
| `LH` | 16 位 | 符号扩展 |
| `LW` | 32 位 | RV32 中直接写入 |
| `LBU` | 8 位 | 零扩展 |
| `LHU` | 16 位 | 零扩展 |
| `SB` | 8 位 | 写 `rs2` 低 8 位 |
| `SH` | 16 位 | 写 `rs2` 低 16 位 |
| `SW` | 32 位 | 写 `rs2` 低 32 位 |

自然对齐访问不会因地址未对齐而陷入。非自然对齐访问的行为由执行环境定义：可能被硬件完成，可能触发地址未对齐异常，也可能触发访问错误。若非对齐访问跨越多个内存区域或设备语义，执行环境可以选择更严格的处理。

### 2.7 内存排序指令

`FENCE` 用于约束当前 hart 的内存和 I/O 操作观察顺序。指令包含 predecessor 和 successor 集合，各集合可标记设备输入 `I`、设备输出 `O`、内存读 `R` 和内存写 `W`。语义是：在其他 hart 或设备观察时，predecessor 集合中的前序操作必须先于 successor 集合中的后序操作可见。

常见 `FENCE rw, rw` 是全读写栅栏。更细粒度的组合可减少约束范围。`FENCE` 不负责刷新指令缓存；指令流同步由 `FENCE.I` 扩展定义。

### 2.8 环境调用与断点

`ECALL` 请求执行环境服务。它会产生环境调用异常，异常原因取决于当前执行模式。`EBREAK` 用于把控制权交给调试器或执行环境，通常产生断点异常。二者不写通用寄存器；参数、返回值和服务编号由 ABI 或执行环境定义。

### 2.9 HINT 指令

HINT 指令提供性能或功耗提示，不改变架构状态。实现可以忽略 HINT。基础规范为标准 HINT 和自定义 HINT 留出编码空间。使用 `rd = x0` 的某些算术指令编码被定义或保留为 HINT，例如规范 `NOP` 形式。

## 3. `Zifencei` 取指栅栏，版本 2.0

`FENCE.I` 使当前 hart 之后的取指能看到同一 hart 之前对指令内存所做的数据写入。它用于自修改代码、动态代码生成和加载器写入可执行代码后转入执行的场景。

`FENCE.I` 只保证执行它的 hart 的数据写入与后续取指之间的同步。若其他 hart 写入了指令内存，软件还需要通过数据内存同步、远程 hart 通知和目标 hart 执行 `FENCE.I` 等机制建立跨 hart 可见性。出于操作系统调度和迁移考虑，用户级 ABI 可以选择不直接暴露 `FENCE.I`，而通过系统调用完成指令缓存同步。

## 4. RV32E 基础整数指令集，版本 1.9

RV32E 是面向小型嵌入式实现的 RV32I 子集。它把通用整数寄存器数量减少到 16 个，仅保留 `x0` 到 `x15`，其余编码保留。指令语义与 RV32I 对应指令一致，主要差异是可用寄存器数量更少，从而降低寄存器堆面积和功耗。

RV32E 需要独立 ABI 支持，因为调用约定、临时寄存器和保存寄存器集合不同。标准扩展与 RV32E 的组合需要明确说明，尤其是依赖较多寄存器或浮点/向量状态的扩展。

## 5. RV64I 基础整数指令集，版本 2.1

RV64I 将 XLEN 扩展为 64 位。通用寄存器和 `pc` 为 64 位，地址计算和大多数整数运算按 64 位进行。RV64I 继承 RV32I 的控制流、访存和算术框架，并增加双字访问和 32 位 word 运算。

### 5.1 寄存器状态

所有整数寄存器宽度为 64 位。许多 ABI 要求 32 位整数值在 64 位寄存器中保持符号扩展形式，即 bit 31 复制到高 32 位；RV64I 的 word 指令有助于维持这一不变量。

### 5.2 整数计算指令

RV64I 增加以下立即数和寄存器 word 指令：

| 指令 | 语义 |
|---|---|
| `ADDIW` | 低 32 位加立即数，结果符号扩展到 64 位 |
| `SLLIW` | 低 32 位逻辑左移，结果符号扩展 |
| `SRLIW` | 低 32 位逻辑右移，结果符号扩展 |
| `SRAIW` | 低 32 位算术右移，结果符号扩展 |
| `ADDW` | 低 32 位加法，结果符号扩展 |
| `SUBW` | 低 32 位减法，结果符号扩展 |
| `SLLW` | 低 32 位逻辑左移，结果符号扩展 |
| `SRLW` | 低 32 位逻辑右移，结果符号扩展 |
| `SRAW` | 低 32 位算术右移，结果符号扩展 |

`LUI` 和 `AUIPC` 在 RV64 中仍构造 32 位符号扩展结果或 PC 相对值。完整 64 位常量通常由多条移位和加法指令组合生成。

### 5.3 加载与存储指令

RV64I 在 RV32I 访问宽度基础上增加：

| 指令 | 语义 |
|---|---|
| `LWU` | 载入 32 位字并零扩展到 64 位 |
| `LD` | 载入 64 位双字 |
| `SD` | 存储寄存器低 64 位 |

`LW` 在 RV64 中将 32 位字符号扩展到 64 位。字节和半字加载仍按有符号或无符号形式扩展。

### 5.4 HINT 指令

RV64I 继承基础 HINT 空间，并因 word 指令和更宽寄存器引入额外保留形式。HINT 不改变架构状态，软件不能依赖其被执行为某种具体微架构操作。

## 6. RV128I 基础整数指令集，版本 1.7

RV128I 将 XLEN 扩展为 128 位，用于需要超大地址空间或超宽整数运算的未来系统。它沿用 RV64I 的模式，增加对 128 位寄存器、地址和加载/存储宽度的支持。规范中的 RV128I 仍处于较早版本，许多生态和 ABI 细节需要后续规范完善。现有 RV32/RV64 软件不应假设所有实现都会支持 RV128I。

## 7. `M` 整数乘除标准扩展，版本 2.0

`M` 扩展提供整数乘法和除法。将乘除从基础 ISA 拆出，使极小实现可以省略复杂硬件，同时允许通用处理器提供高效运算。

### 7.1 乘法操作

| 指令 | 结果 |
|---|---|
| `MUL` | 乘积低 XLEN 位 |
| `MULH` | 有符号乘以有符号，取高 XLEN 位 |
| `MULHSU` | 有符号乘以无符号，取高 XLEN 位 |
| `MULHU` | 无符号乘以无符号，取高 XLEN 位 |
| `MULW` | RV64：低 32 位乘法，结果符号扩展 |

若需要完整 2*XLEN 位乘积，软件可先执行高半部分乘法，再执行 `MUL` 取得低半部分。实现可以融合相邻乘法指令以共享硬件。

### 7.2 除法操作

| 指令 | 结果 |
|---|---|
| `DIV` | 有符号商 |
| `DIVU` | 无符号商 |
| `REM` | 有符号余数 |
| `REMU` | 无符号余数 |
| `DIVW`/`DIVUW` | RV64：32 位商并符号扩展 |
| `REMW`/`REMUW` | RV64：32 位余数并符号扩展 |

除以零不产生异常：商写为全 1，余数写为被除数。最小负数除以 -1 的有符号溢出也不产生异常：商为被除数，余数为 0。这个设计避免在整数流水线中引入额外异常路径，软件可按需要显式检查。

## 8. `A` 原子指令标准扩展，版本 2.1

`A` 扩展为多 hart 同步提供原子读改写和 LR/SC 序列。原子指令可带 acquire `aq` 和 release `rl` 位，用于在内存一致性模型中建立排序。

### 8.1 原子指令排序

`aq` 位要求后续内存操作不能在该原子操作之前被观察；`rl` 位要求前序内存操作不能在该原子操作之后被观察。二者同时置位可形成 acquire-release 语义。排序只针对指令所访问的地址域；内存和 I/O 的关系仍需按平台定义使用合适栅栏。

### 8.2 LR/SC 指令

`LR.W`/`LR.D` 从地址加载值并建立 reservation。`SC.W`/`SC.D` 在 reservation 仍有效时写入新值并返回 0；失败时不写内存并返回非零值。reservation 可能因其他 hart 写入、异常、上下文切换或实现原因失效。

规范定义了受约束 LR/SC 循环的最终成功条件，帮助软件实现无锁算法。受约束循环应只包含有限数量的基本整数指令和分支，避免嵌套访存、系统调用或可能无限延迟的操作。

### 8.3 原子内存操作

AMO 指令从内存读出旧值，与 `rs2` 组合计算新值，把旧值写入 `rd`，并把新值原子写回内存。标准操作包括：

| 指令族 | 操作 |
|---|---|
| `AMOSWAP` | 交换 |
| `AMOADD` | 加法 |
| `AMOXOR` | 异或 |
| `AMOAND` | 与 |
| `AMOOR` | 或 |
| `AMOMIN` | 有符号最小 |
| `AMOMAX` | 有符号最大 |
| `AMOMINU` | 无符号最小 |
| `AMOMAXU` | 无符号最大 |

RV32 支持 word AMO，RV64 还支持 doubleword AMO。AMO 地址必须满足自然对齐，否则可能触发地址未对齐或访问错误异常。

## 9. `Zicsr` 控制与状态寄存器指令，版本 2.0

`Zicsr` 定义非特权可见的 CSR 访问指令格式。CSR 地址为 12 位，具体 CSR 的存在性、权限和副作用由相应扩展、特权架构或执行环境定义。

| 指令 | 行为 |
|---|---|
| `CSRRW` | 原子读 CSR 旧值到 `rd`，将 `rs1` 写入 CSR |
| `CSRRS` | 读旧值到 `rd`，把 `rs1` 中为 1 的位在 CSR 中置 1 |
| `CSRRC` | 读旧值到 `rd`，把 `rs1` 中为 1 的位在 CSR 中清 0 |
| `CSRRWI` | 立即数版本的读写 |
| `CSRRSI` | 立即数版本的置位 |
| `CSRRCI` | 立即数版本的清位 |

若 `rd = x0`，某些形式可抑制读副作用；若 `rs1 = x0` 或立即数为 0，`CSRRS/CSRRC` 不写 CSR。对只读 CSR 执行写形式、访问不存在 CSR 或权限不足的 CSR，会产生非法指令异常。CSR 指令是原子的：读和写作为一个不可分割的 CSR 操作呈现。

## 10. 计数器

基础计数器为软件提供周期、时间和已退休指令数等信息。常见 CSR 包括 `cycle`、`time`、`instret` 以及高位影子寄存器。RV32 中读取 64 位计数器通常需要读高位、低位、再读高位并检查一致性。

硬件性能计数器可记录实现定义或平台定义事件。计数器可用性、是否允许用户模式读取、是否被虚拟化或过滤，由执行环境和特权配置决定。软件不能假定所有计数器恒存在或恒按真实硬件时间推进。

## 11. `F` 单精度浮点标准扩展，版本 2.2

`F` 扩展增加 32 个浮点寄存器和单精度 IEEE 754 运算。浮点控制与状态寄存器 `fcsr` 包含舍入模式和异常标志。指令覆盖加载/存储、加减乘除、平方根、融合乘加、符号注入、最小/最大、比较、分类以及整数与浮点转换。

浮点异常通常以标志形式记录，而不是产生同步异常。NaN 传播、规范 NaN、非正规数和舍入行为按规范定义。浮点加载和存储只搬运位模式，不解释数值类别。

## 12. `D` 双精度浮点标准扩展，版本 2.2

`D` 扩展在浮点寄存器中支持双精度值，并增加双精度加载、存储、运算、融合乘加、比较、分类和转换指令。若较窄浮点值存放在较宽浮点寄存器中，规范使用 NaN boxing 约定：高位填 1，以便检测错误混用并保持兼容。

## 13. `Q` 四精度浮点标准扩展，版本 2.2

`Q` 扩展提供四精度浮点运算。它延续 `F` 和 `D` 的寄存器、舍入、异常标志和转换模型，适用于需要更高精度的数值程序。实现成本较高，因此通常作为可选扩展存在。

## 14. RVWMO 内存一致性模型，版本 0.1

RVWMO 是 RISC-V 的弱内存排序模型。它允许实现为了性能重排许多普通加载和存储，但通过依赖、原子、栅栏和同步规则保留程序可观察的必要顺序。模型用全局内存顺序、保留程序顺序和若干公理描述合法执行。

### 14.1 基本概念

每个 hart 的程序顺序是指令在该 hart 上的语义顺序。全局内存顺序是所有内存操作在抽象内存中的单一排序。RVWMO 不要求全局顺序总与程序顺序一致；只有满足保留程序顺序规则、读值规则、原子性规则和进展规则即可。

### 14.2 保留程序顺序

某些操作对必须保持顺序，例如同地址重叠访问、显式 `FENCE` 约束的访问、acquire/release 原子操作、语法依赖和流水线依赖所保护的访问。依赖包括地址依赖、数据依赖和控制依赖。编译器和硬件都必须尊重规范定义的依赖语义。

### 14.3 读值、原子性和进展

加载读到的值必须来自在全局内存顺序中合适的存储，并满足同地址可见性约束。原子操作必须表现为不可分割的读改写。进展公理防止在没有持续冲突的情况下，合格的内存操作永远无法完成。

### 14.4 移植和映射

从更强内存模型移植代码到 RVWMO 时，应在锁、消息传递、设备队列和共享数据结构边界使用 `FENCE` 或 acquire/release 原子。仅靠普通加载/存储的源代码顺序不足以表达跨 hart 同步。语言级内存模型到 RISC-V 的映射需要由编译器在原子操作和栅栏处生成合适指令。

## 15. `L` 十进制浮点标准扩展，版本 0.0

`L` 扩展在该版本中只是占位性章节，用于描述未来十进制浮点能力的方向。它尚未形成成熟标准，软件不应依赖其存在。

## 16. `C` 压缩指令标准扩展，版本 2.0

`C` 扩展提供常用指令的 16 位编码，以降低代码大小和取指带宽。支持 `C` 后，IALIGN 可为 16 位，跳转和分支目标可落在半字边界。压缩指令解码后语义等价于相应 32 位基础指令或标准扩展指令。

### 16.1 压缩格式和寄存器子集

许多压缩指令使用 3 位寄存器字段，只能编码常用寄存器子集 `x8` 到 `x15`。另一些指令使用完整寄存器字段或隐含 `sp`、`ra`、`x0`。立即数字段被重排以覆盖常见栈偏移、加载/存储偏移和分支范围。

### 16.2 指令类别

压缩加载/存储包括对栈指针和常用寄存器子集的字、双字、浮点字/双字访问。压缩控制转移包括 `C.J`、`C.JAL`、`C.JR`、`C.JALR`、`C.BEQZ` 和 `C.BNEZ`。压缩整数计算包括 `C.ADDI`、`C.LI`、`C.LUI`、`C.SLLI`、`C.SRLI`、`C.SRAI`、`C.ANDI`、`C.SUB`、`C.XOR`、`C.OR`、`C.AND` 以及 RV64/RV128 的 word 变体。

`C.NOP` 是压缩空操作。部分编码定义为 HINT，允许实现忽略。压缩指令可出现在普通指令流中，不需要模式切换。

### 16.3 LR/SC 序列中的 C 指令

受约束 LR/SC 循环对可出现的指令有限制。压缩指令若语义属于允许的基础整数操作，可在受约束序列中使用；但软件仍需遵守长度、访存和控制流限制，以保持最终成功保证。

## 17. 早期或占位标准扩展

本版非特权规范包含若干当时尚未成熟或后来已由独立规范替代的章节：

| 扩展 | 状态与含义 |
|---|---|
| `B` | 位操作扩展在本卷中为早期占位，后续由独立 Bit-Manipulation 规范细化 |
| `J` | 面向动态翻译语言的扩展占位 |
| `T` | 事务内存扩展占位 |
| `P` | Packed-SIMD 扩展早期草案 |
| `V` | 向量操作扩展早期草案，后续由独立 Vector 规范发展 |
| `Zam` | 非对齐原子扩展草案 |
| `Ztso` | 全存储排序扩展草案 |

实现和软件应以相应独立规范或更新版本为准，不应把本卷中的早期占位文字当作最终语义。

## 18. RV32/64G 指令集清单

`G` 组合面向通用处理器，包含基础整数 ISA、整数乘除、原子、单精度浮点、双精度浮点、CSR 指令和取指栅栏。其指令清单覆盖：

- RV32I/RV64I 基础整数运算、控制流、加载/存储、`FENCE`、`ECALL`、`EBREAK`。
- `M` 的乘法、除法和余数。
- `A` 的 LR/SC 与 AMO。
- `F`/`D` 的浮点加载、存储、运算、比较、分类、转换和融合乘加。
- `Zicsr` 的 CSR 读写、置位和清位。
- `Zifencei` 的 `FENCE.I`。

汇编器通常还提供伪指令，例如 `NOP`、`MV`、`LI`、`LA`、`J`、`JR`、`RET`、`CALL` 和 `TAIL`。伪指令不是单独 ISA 语义，而是展开为标准指令序列。

## 19. RISC-V 汇编程序员手册

汇编层面的要点包括：立即数装载通常由 `LUI`/`ADDI`、`AUIPC`/加载或链接器重定位组合完成；PC 相对寻址使用 `AUIPC` 加后续访问；函数调用使用 `JAL` 或 `JALR` 并把返回地址放入 `ra`；返回通常使用 `JALR x0, 0(ra)` 的伪指令形式 `RET`。

ABI 规定栈对齐、参数传递、返回值、调用者保存和被调用者保存寄存器。ISA 只保证指令语义，不规定对象文件格式、重定位类型或系统调用号。

## 20. 扩展 RISC-V

RISC-V 的扩展机制分为标准扩展、保留空间和自定义扩展。标准扩展由规范定义，目标是跨实现兼容。自定义扩展用于专用系统，但不应占用未来标准可能使用的保留编码。非标准扩展应通过名称、版本和平台发现机制清楚暴露。

### 20.1 扩展设计原则

扩展应尽量复用现有寄存器和编码风格，避免破坏基础 ISA 的简单译码和模块化。若某功能只服务窄领域，可作为可选扩展而非放入基础 ISA。扩展之间应明确依赖关系，例如浮点扩展依赖浮点寄存器状态，某些压缩指令依赖对应基础或浮点扩展。

### 20.2 固定 32 位格式内扩展

标准 32 位指令空间被划分为多个主 opcode。部分 opcode 已分配给基础 ISA 和标准扩展，部分留作未来标准或自定义使用。扩展设计需要兼顾 RV32、RV64 和未来 RV128 的兼容性，并避免让立即数字段、寄存器字段和功能字段变得难以译码。

### 20.3 更长指令和 VLIW

RISC-V 编码为 48 位、64 位和更长指令预留了长度模式。更长指令可用于需要更多寄存器字段、立即数或操作描述的扩展。VLIW 或打包多操作编码可以在扩展空间中定义，但必须与基础取指长度规则兼容。

## 21. ISA 扩展命名约定

ISA 字符串以基础 ISA 开头，例如 `rv32i`、`rv64gc`。单字母标准扩展按规范顺序排列；多字母扩展使用 `Z`、`S`、`H`、`X` 等前缀，并用下划线分隔。版本号可附加在扩展名后，用于精确描述实现的规范版本。

| 前缀 | 含义 |
|---|---|
| `Z*` | 非特权标准扩展或标准子扩展 |
| `S*` | 监管者级扩展 |
| `H*` | 虚拟化相关扩展 |
| `X*` | 非标准扩展 |
| `Zxm*` 等 | 可按规范进一步细分用途 |

命名区分大小写。非标准扩展不得冒充标准扩展。实现报告 ISA 字符串时应包含足够信息，使软件能够判断代码生成和运行时能力。

## 22. 历史与致谢

RISC-V 起源于对开放、简洁、可扩展 ISA 的需求。其设计吸收了 RISC 架构、编译器实践、教学处理器和工业实现的经验。规范经历多个版本演进：基础整数 ISA 逐步稳定，浮点、原子、压缩、内存模型和扩展命名规则持续完善。许多贡献者通过实现、审阅、形式化建模和软件移植推动了规范成熟。

## 23. RVWMO 解释材料

RVWMO 的动机是在可移植并行软件和高性能实现之间取得平衡。强排序模型更容易理解，但会限制硬件重排、缓存一致性优化和乱序执行；过弱模型又会让编译器和程序员难以构建同步。RVWMO 通过保留必要依赖和提供明确栅栏，使普通代码保持高效，同步代码保持可证明。

litmus 测试用于展示小型并发程序在模型下允许或禁止的结果。常见测试包括 store buffering、message passing、load buffering、IRIW 和带依赖的变体。解释材料把这些结果映射到保留程序顺序、读值公理和原子性公理，帮助实现者验证内存子系统，也帮助编译器作者生成正确同步序列。

对于主存之外的 I/O 区域，排序还受平台内存属性影响。设备寄存器访问通常需要更强约束，软件应使用 `FENCE` 中的 `I`/`O` 位或平台规定的设备访问原语。缓存一致性、不可缓存区域和幂等性都属于平台语义与 ISA 语义交界处。

## 24. 形式化内存模型规范

规范附录用 Alloy、Herd 和操作式模型给出 RVWMO 的形式化描述。公理化模型定义事件、程序顺序、读取来源、全局内存顺序、保留程序顺序和合法执行条件。操作式模型从 hart 状态、共享内存状态、指令实例状态和转换规则出发，描述执行如何一步步产生可观察行为。

形式化模型的作用是消除自然语言歧义，为硬件验证、编译器映射和 litmus 测试工具提供共同基础。实现者可以用这些模型检查微架构是否允许了规范禁止的行为，或错误禁止了规范允许的优化。
